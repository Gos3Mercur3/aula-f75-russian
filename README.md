# AULA F75 — русская версия драйвера (OemDrv / движок BYCOMBO4)

Русификация фирменной утилиты AULA F75 / F75 Pro / F75 Max / F87 / F99. Меняет **только текст
интерфейса**: 270 надписей — вкладки, редактор макросов, 20 эффектов подсветки, 11 «музыкальных»
режимов, слои FN, все диалоги и сообщения об ошибках.

В прошивку клавиатуры не пишется ничего. Риск = «удалить файл и вернуть обратно».

Показывается после установки:

| До | После |
|---|---|
| `Key assignment` | `Назначение клавиш` |
| `Base layer` / `FN1 layer` / `Tap` | `Базовый` / `FN1` / `Клик` |
| `Debounce Time` | `Задержка срабатывания` |
| `Fixed_on` / `Flash_away` / `Retro_snake` | `Ровный свет` / `Вспышка по нажатию` / `Змейка` |
| `Cycle until the key released` | `Повторять, пока держишь клавишу` |
| `The device is asleep or disconnected` | `Клавиатура уснула или отключена` |

## Установка

1. Скачай `AULA_F75_RU_installer.zip` из [latest release](../../releases/latest).
2. Распакуй **целиком** (не вытаскивай один батник — рядом должен лежать `text_ru.xml`).
3. Дважды кликни `УСТАНОВИТЬ.bat`. Если папка программы защищена — правой кнопкой
   «Запуск от имени администратора».
4. Перезапусти утилиту полностью (иконка в трее → ПКМ → Выход), а не крестиком.

Готово. Русский будет при любом выбранном языке, потому что батник обновляет `text.xml`
во всех папках `Text\<код>\` сразу.

**Откат:** `undo.bat`. Оригинал никогда не удаляется — он лежит рядом как `text.xml.bak`.

## Что делает установщик

* ищет папку программы среди типовых путей (`AULA\F75`, `F75 Pro`, `F75 Max`, `F87`, `F99`,
  оба Program Files, `D:`); если не нашёл — подсказывает, куда вписать свой путь;
* создаёт `text.xml.bak`, только если его ещё нет (можно запускать много раз — оригинал не зрётся);
* пишет перевод во все `Text\<язык>\text.xml`, а если подпапок языка нет — в `Text\text.xml`;
* печатает размеры файлов: все одинаковые → установка прошла;
* предлагает сразу запустить `OemDrv.exe`.

Никаких `del` / `rd`, никаких правок вне `Text\`. Это же проверяют тесты (см. ниже).

## Три случая, когда русский «пропал»

1. Переустановили или обновили драйвер — `InitSetup.dll` пересоздаёт `Text\`. Лечится повторным запуском `УСТАНОВИТЬ.bat`.
2. Батник запустили без админа, и Windows спрятала запись в VirtualStore. Проверка:
   `test-path "$env:LOCALAPPDATA\VirtualStore\Program Files (x86)\AULA\F75"` → `True` means удалить эту папку и повторить от админа.
3. Вместо кириллицы квадратики `□□□` — это не перевод, это шрифт сборки без кириллицы.
   На F75 проверено: отображается нормально.

## Структура

```
dist/                     то, что попадает в архив
├── УСТАНОВИТЬ.bat         установщик (OEM-866, CRLF, chcp 866)
├── undo.bat               откат
├── text_ru.xml            перевод, 277 тегов, UTF-16 LE + BOM + CRLF   ← основной файл
├── text_ru_full.xml       то же, но структура 1:1 с английским файлом (287 тегов, с дублями)
├── text_ПРЕВЬЮ_utf8.xml   UTF-8 копия — только чтобы почитать в Блокноте
├── table_EN_RU.md         277 строк: EN → RU → что было в китайской сборке
├── README.md, КУДА_СТАВИТЬ.md, FN_шпаргалка.md
tools/
├── ru.json                ИСХОДНИК ПЕРЕВОДА: тег → строка. Правь его, не XML
├── build_dist.py          сборка dist/ + архива из ru.json; --check сверяет
├── make_reference.py      генерирует эталон структуры для тестов
├── check_repo.py          25 тестов: XML, кодировки, статика .bat, симуляция установки
└── text_en_reference.xml  (gitignore) генерируется, в репозитории не лежит
TESTS.md                   последний прогон тестов
.github/workflows/tests.yml  то же самое в CI (25 проверок, без Windows-раннера)
```

## Как поправить перевод

```bash
# 1. правь dist/../../tools/ru.json — только значения, теги не трогай
python3 tools/build_dist.py        # 2. пересобрал dist/ и архив
python3 tools/make_reference.py    # 3. эталон для тестов
python3 tools/check_repo.py        # 4. 25/25
```

Длину подписей держи в уме: панель редактора макросов держит ~19 символов, вкладки слоёв ~11.
Программа обрезает многоточием — тест №9 следит, чтобы самые узкие места не вылезали.

## Тесты

`python3 tools/check_repo.py` → 25/25, отчёт в `TESTS.md`. Покрывается:

* валидность XML, UTF-16 LE + BOM, CRLF, отсутствие CJK-символов, чистое экранирование;
* 277 тегов и порядок 1:1 с эталоном, 7 пустых тегов совпадают с оригиналом, 287-й вариант с дублями;
* 270 заполненных строк, ключевые подписи влезает в панель, `FN+1..FN+5`/`DPI`/`мс` не переведены назло;
* батники: кодировка OEM-866 без потерь, все `goto`/`call` ведут на существующие метки,
  блоки сбалансированы, нет многострочных `for..in()`, `%%` и `!VAR!` на месте;
* **безопасность**: отсутствие `del`/`rd`, запись только в `Text\*\text.xml`, бэкап до записи
  и защита от перезаписи существующего бэкапа;
* симуляция логики установщика на фиктивной папке `Text\en\` (установка, откат, три повторных
  запуска, отсутствие подпапок языка);
* архив: ровно 9 файлов, все в папке `AULA_F75_RU/`, CRC целые, пути из README существуют;
* раунд-трип: `dist/` байт-в-байт равен пересборке из `tools/ru.json`.

CI (`tests.yml`) гоняет этот же набор на ubuntu-latest.

**Чего тесты не покрывают:** запуск `.bat` в настоящем `cmd.exe` и поведение `OemDrv.exe` —
нужна Windows. Логику циклов установщика тесты воспроизводят на эмуляции папок, но живой
двойной клик — это проверка только на живой машине.

## Чего перевод не меняет

* `Comm` / `Adv` / `Keypad` / `Modify` в списке клавиш — эти подписи не берутся из `text.xml`
  (соответствующих тегов нет ни в английской, ни в китайской сборке), они рисуются из программы.
  Правится только патчем `OemDrv.exe` с сохранением длины строк — сознательно не делаем.
* `KB.ini`, `skins\`, `Dev\kb\*\*_unit.txt` — профиль клавиатуры и данные анимаций, языка там нет.
* Настройки самой клавиатуры (раскладка, макросы, свет) — утилита их пишет в память клавиатуры,
  этот проект к ним не прикасается. Работает только по USB-C и только в Windows.

## Правовое

Файлы OEM-распространителя (`OemDrv.exe`, оригинальные `text.xml`, скины) в репозитории **не** лежат:
в архиве только наш `text_ru.xml` и батники, а эталон структуры генерируется из него же.
